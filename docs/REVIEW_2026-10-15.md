# REVIEW 2026-10-15: the AST index's first audit, at `2a96c5f` + the shadows branch

## How it was done, and what it can and cannot say

The new index (`tools/astindex`, libclang over every C++ translation unit and `dxc -ast-dump`
over every shader, served by the Scriptorium's `refs`, `callers`, `callees`, `layout`,
`cbuffer_reads` and `includes`) was asked four questions of the whole tree: which C++ structs
mirror an HLSL cbuffer and disagree with it; which HLSL functions no entry point reaches; which
cbuffer fields the C++ fills and no shader reads; which C++ member functions nothing references.
Every answer below is the index's reading of ONE configuration (the build's defines, the entry
points `src/` names in string literals). Two standings:

- **index**: the finding stands on the index alone;
- **re-read**: Fable grepped or opened the lines and agrees.

What was acted on the same day is marked **done**: the orphaned HLSL functions (finding 3) are
deleted, the rest is left for the owner. The blind spots the index names for itself (a call on a
template parameter's member, code under a disabled `#if`, an HLSL entry reached by a computed
name) apply to findings 4 and 5: treat those as candidates, not verdicts.
